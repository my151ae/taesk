# MVP Priorities (2026-03-15)

`cards.short_id = 'aS0WJmqf'` のカード「Taesk機能整理(MVPを忘れずに)」を起点に、現状の Taesk 全体を見て、次に何から着手すべきかを整理する。

## 結論

現時点で優先すべきなのは、新しい大型機能を増やすことではなく、以下 4 つを固めること。

1. 探せること
2. 残せること
3. 動かせること
4. 実行できること

特に、検索、過去未完了タスク、恒常的に見たいカード、CardModal のキーボード操作は毎日の使用頻度が高く、先に品質を上げる価値が大きい。

## 優先順位

### 1. カード検索を仕上げる

最優先。カードが増えるほど「どこにあるか分からない」が最初のボトルネックになる。

- 検索対象は `title`, `excerpt`, `content`, `tags`
- Timeline / A/B / List 表示で一貫した検索結果にする
- 日付範囲外の一致カードをどう見せるかを決める
- 検索結果だけの簡易リスト表示を持てると実用性が高い

このテーマは既存のフィルター機構を拡張すれば進めやすく、ROI が高い。

### 2. 過去未完了タスクと恒常カードの扱いを定義する

このカードには「過去の未完了タスク」「恒常的に表示するカード」が複数回出ており、実運用上の課題として強い。

- `Overdue` と `Pinned` を分けて考える
- 過去未完了は Timeline 左端や専用パネルに集約する
- 恒常カードは日付起点ではなく常設の見え方を持たせる
- タグで代用するのか、専用属性を持つのかを決める

ここが曖昧なままだと、検索や通知やボード設計もぶれやすい。

### 3. CardModal のキーボード操作を安定させる

カード内の未チェック項目でも、タイトルと本文境界の矢印移動やスクロール後の挙動に関する不満が複数残っている。

- タイトル末尾の `ArrowRight`
- 本文 1 行目以外から `ArrowUp` でタイトルへ飛ぶ誤動作
- スクロール後にタイトルへフォーカスした際の矢印移動
- 空行や空チェックボックスをまたぐ時のフォーカス制御

これは見た目の改善ではなく、編集体験の信頼性の問題なので早めに片付ける。

### 4. A/B リストの実行導線を強化する

「A/B リストでも時間設定してアラームできるように？」は Taesk の強みになりやすい。

- 最初は A/B カードに軽い時刻設定を持てれば十分
- MVP では開始時刻 + 通知だけでも価値がある
- Timeline に移す前段の「今日やる候補」を実行可能な状態にする

ここはフル機能化せず、小さく導入するのがよい。

### 5. 通知と Google Calendar を整理する

機能追加よりも、できることを分かりやすく再設計する段階。

- 通知設定は「何が鳴るか」「いつ鳴るか」を明快にする
- Google Calendar は双方向編集より、まず表示・連携の見通しを優先する
- 「コピーリンクって何か分からない」などの導線も整理対象

MVP の段階では、複雑な同期よりも「使い方がすぐ分かる」ことを重視する。

### 6. その後にポモドーロを検討する

ポモドーロは魅力的だが、現時点ではコア導線の後。

- まずは独立タイマーとして小さく始める
- カードの作業時間保存は次段階でよい
- Dashboard や status bar と組み合わせる前に単体価値を確認する

## 後回しでよいテーマ

以下は重要だが、MVP の最初の波では後回しでよい。

- 親子カード
- 本文からカード分割
- 別ボードへの情報連携
- 月表示カレンダーボード
- リスト専用ボード
- ダッシュボードの大規模化
- 高度な Google Calendar 双方向同期

これらは情報構造やプロダクトの境界を変えやすく、先に入れると全体の軸がぶれやすい。

## Taesk 全体で足りないところ

### 情報の見つけ方

- 検索の完成度が不足している
- 日付範囲外カードの見せ方が弱い
- 過去未完了と恒常カードの扱いが未定義

### 実行中の支援

- A/B カードから実行に移る導線が弱い
- 時間設定と通知の接続が薄い
- ポモドーロや作業中支援は未着手

### 編集の信頼性

- CardModal のキーボード挙動に未解決項目が残っている
- タイトルと本文境界の挙動は仕様がある一方で、体感品質に残課題がある

### 機能の責務分担

- タグ、トグル、チェックリストの役割がまだ曖昧
- 恒常カードをタグでやるのか、専用概念を持つのか未整理
- Board / List / Calendar の関係も今後設計が必要

## 推奨の着手順

### Phase 1

- カード検索
- 過去未完了タスク表示
- 恒常カードの定義
- CardModal キーボード挙動修正

### Phase 2

- A/B カードの軽い時間設定
- A/B 起点の通知
- 通知設定 UI の整理
- Google Calendar 連携の役割再定義

### Phase 3

- ポモドーロ MVP
- status bar / shortcut actions の整理
- ダッシュボード入口の検討

### Phase 4

- 親子カード
- 本文分割
- 別ボード連携
- 月 / 週 / 日の別ビュー展開

## 実装判断の原則

- まず「毎日触る導線」を強くする
- 先に検索・未完了・編集品質を固める
- 大きい概念追加は、既存の運用課題が片付いてから
- 新機能はできるだけ小さい MVP に分解して入れる

## 現時点の一言まとめ

次にやるべきことは、派手な機能追加ではなく、`探す`, `残す`, `動かす`, `実行する` の基本導線を固めること。その中でも最初の着手対象は `検索`, `過去未完了 / 恒常カード`, `CardModal 操作品質` の 3 つ。
