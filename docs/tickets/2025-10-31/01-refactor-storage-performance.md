# リファクタリング: 保存・読み込みパフォーマンス改善

**Status**: 🔴 Not Started
**Priority**: 🔥 High
**Created**: 2025-10-31 0842
**Assignee**: 未定
**Estimated**: 未定

## 概要

ボードやカードの保存・読み込み処理が遅いというフィードバックを受け、関連コードのリファクタリングとパフォーマンス改善を行う。

## 目的

操作レスポンスを向上させ、将来的な機能追加に耐えられるように同期・永続化処理を整理し、技術的負債を解消する。

## 実装内容

- [ ] 保存および読み込みに関わる現行フローの計測とボトルネック把握（APIレスポンス、キュー処理、Supabase呼び出し）
- [ ] `app/(board)/_components/KanbanBoardClient.tsx` 周辺の状態管理・同期キューの整理
- [ ] `app/api/boards/*` の永続化APIを確認し、不要なクエリや過剰なデータ転送を削減
- [ ] キャッシュやプリフェッチの最適化案検討（可能なら実装）
- [ ] 改善後のレスポンス時間を測定し、回帰テスト（Playwright JSON レポート）でカバー

## 技術的詳細

- 現状はオフラインキューとAPI経由の永続化が複雑に絡んでいるため、処理順序と再試行ロジックの見直しが必要。
- Supabase 呼び出しのメトリクスを取得するため、`lib/` 配下のヘルパーに計測用ラッパーを追加する可能性がある。
- `KanbanBoardClient` の再レンダー頻度を抑えるため、プレゼンテーション層と同期ロジックの分離を検討する。
- 大規模な変更になる場合は段階的リファクタリングを行い、既存動作を保つために feature flag や環境変数の活用も検討。

## 受け入れ基準

- [ ] 主要な保存・読み込み操作（カード追加、更新、ボード読み込み）の平均レスポンスタイムが目標値（暫定: 30%改善）を満たす
- [ ] Playwright の主要シナリオが遅延なく完了することを JSON レポートで確認
- [ ] 新旧コードの差分をドキュメント化し、影響範囲が明記されている
- [ ] リファクタリング後もオフラインキューとリアルタイム同期が期待どおりに動作することを確認
