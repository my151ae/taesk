# リファクタリング: 保存・読み込みパフォーマンス改善

**Status**: 🟡 In Progress
**Priority**: 🔥 High
**Created**: 2025-10-31 0842
**Assignee**: 未定
**Estimated**: 未定

## 概要

ボードやカードの保存・読み込み処理が遅いというフィードバックを受け、関連コードのリファクタリングとパフォーマンス改善を行う。

## 目的

操作レスポンスを向上させ、将来的な機能追加に耐えられるように同期・永続化処理を整理し、技術的負債を解消する。

## 実装内容

- [x] 保存/読み込みの現行フローを分解計測（フロントUX、永続化レイヤ、DB/Supabase）
- [x] Kanban 画面コンポーネント周辺の状態管理と同期キュー（Outbox）を整理（重複防止キー、指数バックオフ、最大リトライ）
- [ ] 永続化レイヤの最適化（不要クエリ削減、差分更新、バッチ化、ペイロード縮小）※API を挟む場合は PATCH/冪等キーを採用
- [ ] キャッシュ/プリフェッチ（段階ロード、局所無効化、直近ボードの先読み）
- [ ] 改善後の p95 を測定し、Playwright JSON + CI 閾値で回帰チェック

## 技術的詳細

- 計測ラッパ: `lib/metrics/*`（永続化呼び出しの唯一入口）で `traceId, op名, 件数, 所要時間, 成否, payloadSize` を記録し、フロント〜DB へ貫通
- 整合性: Outbox は順序保証＋冪等キー（同一リクエストの重複適用防止）。Realtime と競合時はサーバ勝ち/差分マージ規約を定義
- DB最適化: ホットパスのクエリに合わせ複合インデックス追加、必要に応じて RPC 検討

## 受け入れ基準

- [ ] 初回ロード / カード追加 / カード更新の p95 が現状比 -30% 以上（ベースラインを事前取得）
- [ ] 失敗率 < 1%（4xx/5xx/ネットワークで集計し、改善後も維持）
- [ ] Playwright JSON を用い、p95 閾値超過で CI が失敗する仕組みを実装
- [ ] 新旧差分（API/スキーマ/マイグレーション/ロールバック）をドキュメント化
- [ ] オフライン→復帰、および Realtime 併用時の順序/重複/競合が期待どおり動くことをテストで保証
