# カード本文のインライン編集に向けた整理（2025-11-28）

## 目的・前提
- ボード上のカード本文を、クリックで直接編集できるようにし、Notion のようなチェックリスト運用をスムーズにする。
- Today/Tomorrow のタイムラインと A/B リストの両方で同じ本文を扱い、所属変更やリアルタイム更新と競合させない。
- App Router でのハイドレーション崩れを避ける（表示制御は Tailwind のユーティリティクラスで行う）。

## 要求整理（現時点の理解）
- 本文クリックでインライン編集を開始する（既存 CardModal との二重編集が起きないよう制御が必要）。
- Enter で改行し、次の行頭にもチェックボックス（`- [ ] ` 相当）が自動で挿入される挙動を再現したい。
- Tab でインデント、Shift+Tab でアウトデント（リスト階層を持てるようにする）。
- A/B リストではカードごとに「本文の行数」を表示する（空行を数えるかは要確認）。
- タイムラインでは通常表示は省略（行数を圧縮/ellipsis）。クリックして編集時のみ本文を広げ、編集完了後は再び省略表示に戻す。

## 決定した方針
- **本文フォーマット: 方針B（構造化）**  
  - checklist を JSON など構造化して保存し、行ID/階層/チェック状態を保持する。将来の「行→カード切り出し」を想定し、パース揺れを避ける。
- **入力コンポーネント: 方針B（`textarea` 拡張）**  
  - 行頭への `- [ ]` 自動付与、Tab/Shift+Tab で文字列操作。SSR/IME/Undo/ペーストの安定性を優先。構造化フォーマットと紐付く中間レイヤーで、行データ⇔テキストを相互変換する。
- **保存トリガー: ハイブリッド**  
  - Blur と Cmd/Ctrl+Enter で即保存。さらに無入力1–2秒の debounce 自動保存を併用。Esc はキャンセル。衝突時は楽観更新のロールバックを行いフォーカス維持を優先。
- **タイムラインでの展開: 方針A（その場で拡張）**  
  - 通常は行数制限＋ellipsis、編集開始で同じ位置に高さ拡張。編集中は dnd 無効化し、上限高さ＋内部スクロールで周囲との干渉を抑える。
- **A/B 行数表示: クライアント簡易計算**  
  - 非空行のみカウントしてタイトル付近に表示。リアルタイムで再計算し、保存値は持たない（空行は除外）。意味合いは「チェックリストの実質行数メタ情報」。
- **インデント管理: 方針B（階層レベル保持）**  
  - 各行に level を持ち、保存時にスペースへ変換してAPIに送る。将来の行切り出しに備え、階層データをロスなく維持。

## 実装上の論点・懸念
- **データ構造**: checklist JSON（行ID/level/checked/text）を新設し、既存本文は破棄。API/DBは新フィールドのみで実装する前提。旧データ移行は不要。
- **既存 UI との競合**: タイムラインのドラッグ（@dnd-kit）とクリック編集のフォーカス/バブリング制御、CardModal との同時編集防止（ソースオブトゥルースはインライン編集とCardModalで共通のJSON）。
- **入力コンポーネント実装**: `textarea` 拡張で行データ⇔テキストのシリアライズ/パースを実装。Undo/Redo、IME中 Enter、ペースト時のクリーニングを要検討。
- **キーボード挙動**: Enter で次行にチェックボックスを付与、Shift+Enter は素の改行、Tab/Shift+Tab は level 増減。Tab のデフォルトフォーカス移動を防ぐ必要あり。
- **タイムラインの省略表示**: 高さは時間スロットで決まり、それを超える本文は省略。クリックでその場拡張し、上限高さ＋内部スクロールで干渉を抑える。
- **同期とロールバック**: useSyncQueue/Realtime での更新競合時、編集中のローカル入力をどう扱うか（楽観更新の巻き戻しがフォーカスを失わないように）。
- **メトリクス/ログ**: インライン編集開始・保存を `createClientTrace('timeline')` に載せるか。既存メトリクスと重複しないイベント名を検討。
- **アクセシビリティ**: チェックボックス行をスクリーンリーダーが認識できるか、Tab/Shift+Tab で予期しないフォーカス移動が起きないか。

## 追加決定事項
- **データ移行**: 既存本文データは不要のため全削除で開始する。旧本文フィールドは運用しない。
- **API/DB**: checklist JSON 用の新フィールドのみを保持し、旧本文フィールドは共存期間なしで廃止。
- **レンダリング**: CardModal も checklist JSON を直接表示・編集する（テキスト変換の暫定表示は不要）。
- **タイムライン省略ルール**: 高さはタイムスロット依存。スロットを超えた分は省略し、クリックでその場拡張・内部スクロール。
- **A/B 行数表示**: 最も簡易な配置（例: タイトル横のメタ表示）で、モバイルも同様に軽量表示。
- **テスト**: 現時点で Playwright 追加シナリオは不要。後続で timeline バッチにインライン編集/Tab/Shift+Tab/省略展開/オートセーブを追加する余地は残す。

## 進め方のメモ
- UI 実装箇所の候補: `app/(board)/_components/timeline/` 配下（タイムライン）、A/B は同ディレクトリのカードコンポーネントを要確認。
- SSR/ハイドレーション安全策: サイズ計測に `window` を使わず、Tailwind クラスで表示切替。編集時の高さは CSS で制御し、初期レンダリングを決定論的に。
- DnD との棲み分け: インライン編集時はドラッグを無効化するガードを置く（`isEditing` フラグを dnd センサーで参照）。
- 保存・ロールバック: useSyncQueue を介した楽観更新 + 失敗時のリトライ/アラート方針を決める。リアルタイム受信時は編集中はスキップ or 衝突解決を定義。
- 検証方針: Playwright は `PW_WORKERS=1` で `npx playwright test --reporter=json` を利用し、新シナリオを timeline バッチに追加する。ログは `test-results/batches/` へ。
