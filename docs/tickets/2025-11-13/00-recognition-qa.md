# 00 - TaeskMap 認識合わせQ&A（2025-11-13）

最新の仕様確認や宿題をまとめ、合意済み / 要検討を明確にします。回答済みは ✅、追加検討が必要なものは ⚠️ で示しています。

## 回答済み

| No | 質問 | 回答 | ステータス |
| -- | ---- | ---- | ---- |
| 1 | 現在の `due_date` フィールドは無くす想定？ | **リネームせず `due_date` をそのまま採用。** タイムラインの基準日も `due_date` を使い、開始/終了時刻（`due_start`, `due_end`）だけ追加する。既存データは気にせず上書きでOK。 | ✅ |
| 2 | Today/Tomorrowのリストは日付で決まる認識で良い？ | はい。`due_date` が今日なら Today 列、翌日なら Tomorrow 列へ自動所属。Timelineビューでは最大7日ぶんの列を順次並べる設計に拡張できる。 | ✅ |
| 3 | 日付をずらしたらリストもその日付に移動？7日並んだ画面もあり得る？ | その通り。カードの日付変更（DnDまたは詳細編集）で `due_date` が更新され、対応する日列へ再配置される。UIはMVPで Today/Tomorrow、将来的に「7日ビュー」へ拡張予定。 | ✅ |
| 4 | 今週/今月などA/Bだけ表示するリストが将来必要？ | 将来のPhaseで「This week」「This month」など、A/Bセクションのみを表示するビューを追加する。現在のデータモデル（`due_bucket` + `due_channel`）で対応可能。 | ✅（将来） |
| 5 | DnDやカード高さ変更は15分単位でOK？詳細編集だけ1分単位？ | 仕様を更新：ドラッグ/リサイズ/キーボード移動は15分刻み（Shiftで5分補正）、CardModal編集のみ1分単位で保存。 | ✅ |
| 6 | 既存カードはどう扱う？ | プロトタイプ段階なので既存データは無視してよい。初期リリース時は空ボードを前提に `due_*` フィールドを使い始める。 | ✅ |

## 要検討・フォローアップ

1. **`due_date` リネーム案**: →不要と確定（上記回答参照）。
2. **7日ビューや週間/月間A/Bビューの情報設計**: Timeline MVP 完了後に検討。
3. **通知/繰り返し**: Timeline MVP 完了後に検討。
4. **モバイル対応ロードマップ**: Timeline MVP の次タスクとして着手予定。

上記の未決事項は決まり次第この文書を更新します。最新の決定内容は `00-today-list-layout.md` および各チケットに反映済みです。
