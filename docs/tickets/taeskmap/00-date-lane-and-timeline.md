
# 00 — Schedule View（Date Lanes + Timeline）置き換え計画

## 背景
- 既存のカンバン (ステータス列 + モーダル編集) では、日付・時間ドリブンの運用に限界がある。
- 新しい「1行カード＋Tab で子化」「Arrow/Tab で移動」「Google Calendar 風タイムライン」「親子分離／ゴースト表示」「レーン＝日付スロット」を実現するには、**現在のビューを差し替えるレベルの構造変更が必要**。
- そのため、本チケットを「Schedule View」への全面移行の親チケットとし、従来ビューは段階的にリタイアする。

## ガイドライン
1. **併存ではなく置き換え**：Schedule View が完成したら旧 Kanban UI は廃止。暫定的に Feature Flag で切り替えるが、flag は短期間で消す。
2. **段階実装**：巨大な仕様を一括で入れず、以下のフェーズに分割して PR/チケットを切る。
3. **テストは常に 1 Worker**：`PW_WORKERS=1` をデフォルトとし、フェーズごとに E2E を更新してから次へ進む。

## 実装フェーズ案

### Phase 1 — モデル/インフラ整備
- `cards` に `parent_id`, `has_time`, `start_at`, `end_at` など必要フィールドを追加（Migration）。
- API (`/cards`, `/cards/[cardId]`) と Sync Queue を新フィールド対応に。
- 既存データの移行方針を決める（未設定の場合は `has_time=false`, `parent_id=null`）。

### Phase 2 — Schedule View 骨格
- 既存 `KanbanBoardClient` を段階的に分割し、`ScheduleBoardClient` (新レイアウト) を追加。
- 1行カード / インライン編集 / Enter で行追加 / Arrow 移動など最低限の UX を Schedule 側で再現。
- Feature Flag や `?view=schedule` で開発者向けに切り替え可能にする。

### Phase 3 — Date レーン + 自動日付更新
- レーンを `inbox / today / tomorrow / this_week / next_week / this_month` に固定し、移動時に `due_date` を `mapListToDate` で更新。
- リスト移動とカード日付が常に一致するようロジックを整理（inbox は `null`）。
- Tab/Shift+Tab で子化/親化、親子 D&D の基本ルールを実装。

### Phase 4 — タイムライン & タイムレス列
- 00:00–24:00 の縦グリッドと `has_time=false` のフローティング列を実装。
- ドラッグで時間帯を変更、帯の往復で `has_time` をトグル。
- カード高さは実時間に比例し、最小高さ/スナップ（15分）を設ける。

### Phase 5 — 親ゴースト & 上位 UI
- 子カードのみ表示するケースで、親の出自を示すゴーストバッジを追加。クリックで親位置へスクロール or トースト案内。
- Schedule View をデフォルトにし、旧ビューを削除。flag も取り除く。
- ドキュメント・E2E・ガイド類を更新してクローズ。

## 非スコープ
- モバイル最適化（別途検討）。
- ブロックリッチ編集やコメント機能拡張。
- 外部カレンダー同期。

## オープン確認事項（回答 Needed）
1. **日付レーン**：初期は「週の開始＝月曜」固定で実装する（将来的にユーザー選択制も視野に入れる）。
2. **時間未指定 vs 指定**：配置パターン（左帯接着 vs 右フローティング）や UI を `00-01-time-layout.md` で比較し、確定案を決める。
3. **親子移動**：基本は親移動=子も追従。子だけ切り離す操作と、親情報を可視化する UI について `00-01-time-layout.md` で詳細を詰める。
4. **旧ビュー**：今回の Schedule View を標準とし、旧ステータスビューは最終的に廃止する（flag は開発中のみ）。
