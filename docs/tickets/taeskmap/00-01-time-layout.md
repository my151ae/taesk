# 00-01 — Time Layout & Parent/Child UX Deep Dive

## 目的
Schedule View の核となる 2 点を詳細化する:
1. **時間指定あり/なしのレイアウト**（どこに置くか、どちらがユーザーにとって分かりやすいか）。
2. **親子タスクの移動ルール**（親移動時の追従、子単体操作、親情報の可視化）。

結論が出るまでに検討した選択肢・評価・残課題をここにまとめ、合意でき次第 00 本体のフェーズへ落とし込む。

---

## 1. 時間指定あり/なしレイアウト

### Option A — 左:タイムライン（有）、右:フローティング（無）
- **構成**: 画面を左右 2 カラムに分割。左は時間帯に沿ってカードが上下配置、右は時間未指定カードをスタック表示。
- **メリット**
  - 時間あり/なしが一目で区別できる。
  - タイムラインの横幅を確保しやすく、Google Calendar 的な操作と整合が取れる。
  - 時間未指定カードを後からドラッグして簡単に時間帯へ追加できる。
- **デメリット**
  - 2 カラム分の横幅を常に要するためモバイルや狭い画面に弱い。
  - 右カラムの高さが増えすぎると上下スクロールが煩雑になる。

### Option B — 同じタイムライン上で表示位置を分ける
- **構成**: タイムライン上の**上半分**を“フローティングレーン”として使い、時間未指定カードは y=0 付近に重ねて置く。
- **メリット**
  - 1 カラムで完結するため視線移動が少ない。
  - スクロール位置が一体化する。
- **デメリット**
  - 時間あり/なしの境界が曖昧になりやすい（ラベルや色分けが必須）。
  - フローティングカードが多いとタイムラインを覆ってしまう。

### Option C — リスト単位で切り替え
- **構成**: `inbox/今日/明日...` の各レーンに「時間あり」「時間なし」をタブorトグルで持たせる。
- **メリット**
  - レーン別に独立して扱える（今日タスクにだけ時間設定を集中）。
- **デメリット**
  - 操作ステップが増え、全体俯瞰が難しい。

### 技術的難易度比較（概略）
| 項目 | Option A | Option B | Option C |
|------|----------|----------|----------|
| 実装コスト | 中 | 高 (レイヤー制御が複雑) | 中 | 
| UI 明瞭さ | 高 | 中 | 低〜中 |
| モバイル対応 | 低 | 中 | 中 |
| 後続拡張（drag, click） | 高 | 中 | 低 |

**暫定結論**: 現段階では Option A が最もシンプルで説明もしやすい。モバイル対応は Phase 5 以降に専用 UI を検討。

### 残課題
- フローティング列が縦長になった際のナビゲーション（折りたたみ？グルーピング？）。
- モバイル表示時に 2 カラム構成をどう縮約するか。

## 2. 親子タスクの移動ルール

### 基本ポリシー
1. **親カード移動 = 子カード全て追従**（日付・時間とも親の移動先に合わせる）。
2. **子カード単体を別レーン/タイムラインへ移す操作も許容**（その場合 `parent_id` は維持 or 任意で解除できる UI を検討）。
3. **親ゴーストバッジ**で“元の親”を示し、クリックで親位置へジャンプ。

### 操作シナリオ
| 操作 | 挙動 | 備考 |
|------|------|------|
| 親を別日へドラッグ | 子も同じ日へ移動。`start/end` も親との差分を維持してシフト | 日跨ぎの丸めルール要検討 |
| 親を時間指定→なしへ | 子も `has_time=false` に。フローティング列へ移動 | 逆も同様 |
| 子を別親へドラッグ | ドロップ先で親を再割当。元親のゴーストは無効化 | 追加 UX が必要 |
| 子をインデント解除 | `parent_id=null` + フローティングに戻す or 同レーン内で独立 | | 

### ゴーストバッジ案
- `Parent: [親タイトル] • [レーン]` を pill 表示。
- 親が非表示のレーンにある場合は `Go to parent` でビューをスクロール or 切り替え。

### 残課題
- 子の時間を親からのオフセットで持つか、完全に独立か（現在案：独立だが移動時にまとめて更新）。
- “親を削除”するときの子の扱い（自動昇格 or 親なしで残す）。
- ゴーストバッジの位置（行頭 or 行末）とモバイル表示。
