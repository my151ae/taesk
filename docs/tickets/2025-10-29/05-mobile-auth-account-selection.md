# 05. モバイル環境でのアカウント選択フロー改善

## 🎯 ゴール
モバイル端末でログアウト後に再ログインする際、自動サインインではなく Google アカウント選択画面を表示し、利用するアカウントを選べるようにする。

## 🔍 現状
- Supabase Auth (Google OAuth) のセッションがブラウザに保持されており、モバイルブラウザでログイン操作を行うと即時に前回アカウントでログインされる。
- 複数アカウントを切り替えたい場合や、共有端末での利用時に不便。
- PC では `accounts.google.com` に移動する挙動があるが、モバイルでは既存セッションで自動ログインされるケースが多い。

## ✅ 要件
1. 「ログアウト」操作後、次回ログイン時に Google アカウント選択 UI が確実に表示されるよう制御する。
2. 必要に応じて Supabase Auth のセッション・トークンを完全に破棄（`signOut({ scope: 'local' | 'global' })` など）する実装を追加する。
3. モバイルブラウザ特有の挙動（Chrome iOS/Android, Safari）で検証し、再現性を確認する。
4. 共有端末での利用を想定し、ログアウト後に再ログインした場合でも過去アカウントの cookie が残って自動ログインされないことを担保する。

## 🛠 実装メモ
- Supabase Auth の `signOut` 呼び出しを見直し、`signOut({ scope: 'global' })` と `removeAllSessions` API を活用する。
- Google OAuth ページでアカウント選択を促すには、`prompt=select_account` クエリを付与できるか要調査。
- Next.js ルート `/auth/login` のロジックにパラメータを追加し、モバイル時には選択プロンプトを常に表示する選択も検討。
- テスト環境では Playwright モバイルエミュレーションを併用して再現する。

## 🔬 QA 観点
- iOS Safari / Android Chrome でログアウト → ログイン時に必ずアカウント選択画面が出るか。
- 直前に別アカウントでログインしても、切り替えられるか。
- 自動ログインに戻したいユースケースがあるか（フラグで切替が必要か）を検討。

## 📎 補足
- セキュリティ観点で、共有端末利用時には確実なセッション破棄が求められる。
- 将来的には「アカウント切替」ショートカットの追加も検討。
