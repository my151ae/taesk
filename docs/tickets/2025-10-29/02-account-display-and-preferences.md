# 02. アカウント表示名・プロフィール設定導線の整備

## 🎯 ゴール
トップ画面右上に表示される Google アカウントのメールアドレスを、Taesk 専用の表示名に置き換えられるようにし、ユーザー自身が設定メニューからプロフィール情報（表示名・アイコンなど）を編集できるようにする。

## 🔍 現状
- 現在は Supabase Auth から取得した `user.email` をそのままヘッダーに表示している。
- プロフィール編集 UI や保存先テーブルは未整備で、個人情報の編集不可。
- コラボレーション時にメールアドレスが常時表示されるため、プライバシー面での懸念がある。

## ✅ 要件
1. ヘッダーのユーザー表示を「表示名（設定が無い場合はメールローカル部など）」に切り替える。
2. 設定ボタン（既存の通知設定やシェアボタン周辺）から、プロフィール編集モーダル／ページへ遷移できる導線を追加する。
3. 編集可能項目（例）
   - 表示名（必須）
   - 表示アイコン（任意・今後の拡張に備えたフィールド）
4. Supabase `profiles` テーブルに `display_name`（既存フィールドがあればそれを利用）を保存・同期する。
5. 認証メールアドレスは保持するが、UI 上では非表示にする。（必要に応じてホバーや設定画面で参照可能に）

## 🛠 実装メモ
- ヘッダー表示は `app/(board)/_components/KanbanBoardClient.tsx` のユーザーバッジ付近を改修。
- 設定 UI は既存の NotificationSettings モーダルに近い構造で追加するか、共通ダイアログコンポーネントを利用する。
- プロフィール保存 API ルートが未実装の場合は `app/api/profiles/[id]/route.ts` などを新規作成して PATCH を受け付ける。
- 表示名未設定時のフォールバックルール（例: メールの `@` 以前／`Full Name` フィールド）を決めておく。

## 🔬 QA 観点
- 既存ユーザーでプロフィール未設定 → フォールバック表示を確認。
- 表示名変更後、ヘッダーやコメントメンションに即時反映されるか。
- Supabase 側の `profiles` テーブルに正しく値が保存されるか。
- メールアドレス非表示による副作用（ログイン状態確認など）がないか。

## 📎 補足
- 今後の通知・メンション機能でも表示名を使い回す予定。
- メールアドレス表示を完全に排除することにより、画面共有時の個人情報露出を防止。
