# Googleカレンダー連携 v3 — **完全版（双方向同期採用）**
最終更新: 2025-12-07

> 本ドキュメントは、前版の「未決」への回答と差分合意を**すべて反映**した**決定版**です。  
> 仕様の破綻がないよう文言・フロー・フェーズ構成を統一しています。  
> ※ 本版では Taesk 側の終日表現も含め**全項目が確定**しています。

## 0. 用語と状態

内部的には以下の 3 種類のカード種別を持つ。

- **GCard（Googleカード）**  
  - Google カレンダー由来のイベントを Taesk 側に**キャッシュしたレコード**。  
  - デフォルト状態では **未リンク（Google のみがソース）**。  
  - Google から取得したタイミングで必ず DB に保存し、以後は DB から即座に表示する。  
    - 変更検知（push / pull）で差分を受信したときのみ GCard を更新する。

- **TCard（Taeskカード）**  
  - Taesk 内で作成されたローカル専用カード。  
  - 一度 TGLinked だったものがリンク解除された後のカードも、この TCard に含めて扱う。

- **TGLinked（Google接続Taeskカード）**  
  - GCard と TCard が 1:1 で接続された状態。  
  - Taesk と Google の**双方向自動同期**が有効。  
  - UI 上のバッジ名は「Google接続」とし、内部状態名を TGLinked とする。

※ 以降は **GCard / TCard / TGLinked** の 3 区分のみを用いる。
状態遷移:

- **GCard →（「Googleとリンク」ON）→ TGLinked**  
  - 既存 Google イベントを起点に **Taesk 側の TCard レコードを生成**し、1:1 接続して双方向同期を開始する（候補 UI なし）。
- **TCard →（ON）→ Google へ新規イベント作成 → TGLinked**
- **リンク解除済みの TCard →（ON）→ TGLinked（再リンク）**  
  - チェック ON で **近似マッチ候補 UI** を表示。  
  - 既存 Google イベントに再接続するか、「新規作成」を選択して新しいイベントを作る。  
- **TGLinked →（OFF）→ TCard（ローカル専用／Google とは切断）**

## 1. 仕様（決定事項）

### 1.1 リンク管理（チェックボックス運用）

- カード詳細に **「Googleとリンク」** チェックボックスを設置（既定 **OFF**）。  
- ON 中は TGLinked として**双方向自動同期**。OFF でローカル専用の TCard。  
- Google 側の削除・キャンセルを除き、**自動で OFF（Unlink）にはしない**。

### 1.2 リンク/再リンク時の挙動

- **GCard → TGLinked**  
  - 「Googleとリンク」ON で **候補 UI なし**に、その Google イベントへ即接続（TGLinked 化）。

- **TCard → TGLinked（新規作成）**  
  - チェック ON で **Google へ新規イベント作成**。  
  - 作成されたイベント ID を保持し、TCard は TGLinked 状態になる。

- **リンク解除済み TCard → TGLinked（再リンク）**  
  - チェック ON で **近似マッチ候補 UI** を表示。  
  - 既存 Google イベントに再接続するか、「新規作成」を選択して新しいイベントを作る。  

- 近似マッチスコア  
  - 指標: **Jaro-Winkler×0.7 + e^(-|Δmin|/10)×0.3**  
  - しきい値: **0.75 以上**を候補として掲出。  
  - 自動確定は行わず、必ずユーザーの選択を挟む。

### 1.3 同期対象（白リスト）

**Taesk ↔ Google の往復同期対象**

- タイトル
- 説明
- 場所
- 開始日時・終了日時
- 終日フラグ
- 会議 URL（`conferenceData` 自体の編集は対象外）

**Taesk → Google の拡張仕様**

- 既存実装を踏襲し、TCard 側でカード詳細モーダルを開くための **TCard URL を説明欄に追記**する。  
  - 末尾に `----` などの区切り線を入れ、その下に `Taesk: https://app.taesk.io/cards/{id}` を付与。  
  - 既存の説明文とは衝突しないよう、**プレフィックス/サフィックスの形式を固定**し、再同期時も同じ場所へ上書きする。  
  - Google 側の URL クリックで Taesk の TCard モーダルが直接開くことを保証する。

**Taesk 専有（Google とは同期しない）**

- ラベル
- チェックリスト / サブタスク
- 担当者
- 内部コメント
- カスタムフィールド など

### 1.4 繰り返し/例外

- `singleEvents=true` でインスタンス展開。  
- 展開ウィンドウ: **過去 4 週 / 未来 12 週** を基本とする（画面スクロール等に応じて段階的プリフェッチ）。  
- 例外インスタンスは `recurringEventId` + `originalStartTime` を保持し、**常に個別インスタンスとして扱う**。

### 1.5 終日（All-day）

- **GCard の終日イベント**は Google カレンダーと同じ内部表現（`date` / `display_tz` / `start_utc` / `end_utc`）を採用し、カレンダーのヘッダー直下に帯状 UI で表示する。  
  - v3 着手前に帯状 UI を先行実装し、崩れないことを確認してから本仕様を有効化する。  
- **TCard / TGLinked の時間未設定タスク**（Taesk 側の「日付だけタスク」＝現行 A/B リスト上のカード）は、終日帯状 UI にはしない。  
  - Taesk カードに帯状終日を導入する計画はなく、引き続き A/B リスト上のカードとして扱う。  
- この方針により、Google 由来の終日は帯状表示、Taesk 由来の無時間タスクは A/B リストに残す挙動を明示する。

### 1.6 同期方式・競合

- TGLinked 中は **双方向自動同期** を行う。  
- Google 更新時は `If-Match` を利用し、競合が発生した場合は **更新時刻が新しい側** を採用。  
- **自己更新スキップ**  
  - 直前に自分が書いた `etag` / `updated` を取り込みパイプで無視し、更新ループを防ぐ。  
- TCard → 新規作成時は、`extendedProperties.private.idempotency_key` による **冪等キー** で多重作成を防止。

### 1.7 取り込み/通知

- 初回はフル取得 → 以降は `syncToken` による差分運用。
- 初回フル取得ウィンドウは **過去 4 週 / 未来 12 週**（表示範囲と同じ）を基本とし、画面スクロールに応じて段階的にプリフェッチを広げる。  
- `showDeleted=true` を指定し、キャンセル/削除イベントも取得する。  
- **Push（watch）主体 + 動的フォールバック**  
  - 無更新しきい値 = **p95 取り込み遅延 × 3**。  
  - しきい値を超えたらポーリングに切り替え、復旧を確認したら自動で停止する。  
- `410`（syncToken 無効）時は透過的にフル再同期。  
- `429 / 5xx` は指数バックオフ（最大待機 15 分）。

### 1.8 UI/UX

- バッジ  
  - GCard = 「Google（未リンク）」  
  - TGLinked = 「Google接続」  
  - TCard（非接続）= 「未接続」  
  - エラー = 「同期エラー」
- **今すぐ同期**  
  - 詳細パネルに常設（手動リトライ / 即時反映用）。  
  - 保存直後は **「同期中 → 同期完了」** のスナックバーを表示。
- 参加者 / RSVP  
  - 表示のみ（編集不可）。  
  - 5 名を超える場合は “+n” で省略表示。

### 1.9 セキュリティ/権限

- オンボーディング時に、全ユーザーへ `…/calendar.events` スコープを要求（双方向同期を前提とした権限設計）。  
- トークン失効時は「再接続」導線を固定配置しつつ、バックエンドでは指数バックオフで再試行。

### 1.10 観測性/SLO

- 記録する主なメトリクス  
  - **E2E 取り込み遅延**: `t_change（Google 側変更） → t_visible（Taesk 画面反映）`  
  - **システム内部遅延**: `t_ingress（Webhook/ポーリング受信） → t_visible`
- SLO（例）  
  - Push 経路の **p95 ≤ 60 秒**。  
- アラート条件（例）  
  - p95 ≥ 60s が 5 分以上継続  
  - watch 残存 < 30% なのに再作成されていない  
  - DLQ > 100 など

### 1.11 削除/取消/接続解除

- Google 側で `status=cancelled` または削除された場合  
  - 対応する TGLinked は **TCard（ローカル専用）に降格**し、期日/時間などの情報は Taesk 内に保持する。  
- 「Googleとリンク」チェックを OFF にした場合  
  - いつでも接続解除でき、カードは TCard として残る。  
  - 再度 ON にすると、近似マッチ候補 UI を経て再リンク可能。

## 3. 受け入れ基準（抜粋）

- 双方向同期  
  - Taesk 編集 → Google  
  - Google 編集 → Taesk  
  - 上記の反映が Push 経路で **p95 ≤ 60 秒**。
- 競合  
  - `If-Match` 不一致時に再取得し、**新しい側** が採用される。  
  - 自己更新は取り込みでスキップされ、無限ループが発生しない。
- 繰り返し/例外  
  - 例外編集 / 単発キャンセルが正しく展開・反映される。
- 終日  
  - GCard / TCard / TGLinked すべてで、DST / TZ 跨ぎでも表示ズレが発生しない。  
  - GCard 終日は Google カレンダーと同等の帯状 UI で表示される。
- 取消/解除  
  - Google のキャンセル / 削除により TGLinked が TCard に降格し、再リンク可能である。  
- 観測性  
  - Push 停止 → 動的ポーリング → 復旧 → ポーリング停止の流れがメトリクスに可視化される。

## 4. 補足メモ（実装上のポイント）

- GCard は「毎回 Google からライブ取得する」のではなく、**Taesk の DB にキャッシュされたカード**として扱う。  
  - UI は原則 DB を即時表示し、バックグラウンド同期で遅延なく更新されるようにする。  
- `display_tz` は「表示するタイムゾーン」ではなく、**日付をローカル時間としてどのタイムゾーンで解釈するか**を示す。  
  - 表示上は、ユーザーのプロファイル設定など別のロジックでタイムゾーンを選ぶこともあり得る。  
- 終日 TGLinked は、通常の時間指定イベントと同様に A/B テストや機能フラグの対象とする。

## 5. 懸念・要確認ポイント

- **TCard URL 埋め込みの衝突回避**  
  - 既存説明文との境界を固定する運用だが、ユーザーが説明文を全削除した場合の再埋め込みロジックを実装で明示する。  
- **近似マッチ候補の UX**  
  - スコア 0.75 以上で提示するが、候補が 0 件のときの扱い（デフォルトで新規作成を選ぶか、明示の選択を必須とするか）を実装で固定する。  
- **終日表示の順序依存**  
  - GCard 終日帯状 UI をフェーズ0で先行するため、既存データ移行（start/end だけを持つ G/T レコード）へのマイグレーション手順が必要。  
  - Taesk 側終日帯状タスクは導入しない方針（A/B リストの「日付だけタスク」を帯状化しない）。
- **初回フル取得範囲の拡張条件**  
  - 基本は過去 4 週 / 未来 12 週だが、ユーザーが「さらに過去を閲覧」した際にどこまで拡張し、再度狭めるか（キャッシュ縮退条件）を決める。  
- **display_tz の決定ロジック**  
  - 「解釈の基準 TZ」として、Google イベントの `timeZone` / カレンダー設定 / ユーザープロファイル設定の優先順位を実装で固定する必要がある。  
- **watch 再作成しきい値**  
  - 「寿命 30% 前」の算出根拠をメトリクスに記録し、調整可能にしておくと運用が楽。
