## 0. 用語と状態
- **GCard（Googleカレンダーカード）**: Google由来のイベントの**読み取り表示**。既定は**未リンク（OFF）**で、ユーザー操作でLinkedにできる。
- **Linked TCard（Google接続TCard）**: 「Googleとリンク」チェックを**ON**にしたカード。**双方向自動同期**（Taesk↔Google）。
- **Unlinked TCard（未接続TCard）**: チェック**OFF**のカード。ローカル専用。Google側削除/キャンセルや手動解除でこの状態に残る。
>> GCard：Googleのみ
>> TCard：Taeskのみ、未接続に変わったものもこれ
>> TGLinked：双方向同期
>> この3種類でいけないかな？
>> あとGCardも毎回接続のたびに取得しているのを、取得したらこちらのDBにGCardとして保存しておくことで直表示するようにできるよね？で更新があったらそれを取得して、更新する運用にしたい。

状態遷移:
- GCard（未リンク）→（チェックON）→ Linked（既存Googleイベントと接続・双方向同期）
- TCard（未リンク）→（チェックON）→ **Googleへ新規作成**→ Linked
- Unlinked →（チェックON）→ **再リンク候補UI**→ 既存に接続 or 新規作成→ Linked
- Linked →（チェックOFF）→ Unlinked（ローカル残存）

## 1. 仕様（決定事項）

### 1.1 リンク管理（チェックボックス運用）
- カード詳細に**「Googleとリンク」**チェックボックスを設置（既定**OFF**）。
- **ON中は双方向自動同期**。OFFでローカル専用（Unlinked）。自動Unlink機構は**採用しない**。

### 1.2 リンク/再リンク時の挙動
- **GCard→Linked**: チェックONで**候補UIなし**にそのGoogleイベントへ接続（即Linked）。
- **TCard→Linked**: チェックONで**Googleへ新規作成**→そのIDでLinked。
- **Unlinked→Linked**: チェックONで**近似マッチ候補UI**を表示し、既存イベントに再接続（該当なし/不採用なら**新規作成**を選択可能）。
- 近似マッチスコア: **Jaro-Winkler×0.7 + e^(-|Δmin|/10)×0.3 ≥ 0.75**で候補掲出。**自動確定はしない**。

### 1.3 同期対象（白リスト）
- **往復**: タイトル / 説明 / 場所 / 開始・終了 / 終日 / 会議URL（`conferenceData`自体の編集は対象外）。
>> 説明欄へ現在TCardのURLを入れていて、そのURLで直接モーダルを開きたい
- **Taesk専有**: ラベル / チェックリスト・サブタスク / 担当者 / 内部コメント / カスタムフィールド。

### 1.4 繰り返し/例外
- `singleEvents=true`で展開。**過去4週 / 未来12週**を基本ウィンドウ（範囲外参照時は段階的プリフェッチ）。
- 例外は `recurringEventId` + `originalStartTime` を保持し、**常に個別インスタンス扱い**。

### 1.5 終日（All-day）
- **GCard**の内部表現は **date保存 + display_tz + start/end_utc冗長保持**（DST/TZ跨ぎでのズレ防止）。
- **Taeskカード（Unlinked/Linked後のローカル）**の扱いは**確認点として保留**（§4.1 参照）。

### 1.6 同期方式・競合
- Linked中は**双方向自動同期**。`If-Match`を用い、競合時は**更新時刻が新しい側**を採用。
- **自己更新スキップ**: 直前に自分が書いた`etag/updated`は取り込みパイプで無視（ループ防止）。
- TCard→新規作成は**冪等キー**（`extendedProperties.private.idempotency_key`）で重複作成を防止。

### 1.7 取り込み/通知
- 初回フル取得→`syncToken`で差分運用。`showDeleted=true`でキャンセル/削除も取得。
- **Push（watch）主体**＋**動的フォールバック**: 無更新しきい値 = **p95取り込み遅延×3**。復旧確認で自動停止。
- `410`（syncToken無効）時は透過的フル再同期。`429/5xx`は指数バックオフ（最大待機15分）。

### 1.8 UI/UX
- バッジ: GCard=「Google（未リンク）」／Linked=「Google接続」／Unlinked=「未接続」／エラー=「同期エラー」。
- **今すぐ同期**: 詳細パネルに常設（手動リトライ/即時反映の導線）。保存直後は**同期中/完了**のスナックバー通知。
- 参加者/RSVPは**表示のみ**（5名超は“+n”で省略）。

### 1.9 セキュリティ/権限
- オンボーディングで**全ユーザーに `…/calendar.events`** を要求（双方向同期に備える）。
- 失効時は「再接続」固定導線＋指数バックオフ。

### 1.10 観測性/SLO
- **E2E取り込み遅延（t_change→t_visible）**と**システム内遅延（t_ingress→t_visible）**を記録。
- SLO例: **Push経路の p95 ≤ 60秒**。アラート: p95≥60sが5分継続、watch残存<30%で未再作成、DLQ>100 など。

### 1.11 削除/取消/接続解除
- Google側`status=cancelled`/削除 → **Unlinked化**（期日/時間は保持）。
- チェックOFFで**接続解除**（Unlinked）。いつでも再リンク可（近似マッチUI）。

## 2. 実装順序（更新後のフェーズ）

### フェーズ0: 基盤
- 認可（`…/calendar.events`）、データモデル（GCard/Linked/Unlinked/監査）、初回フル取得→差分、基本表示/バッジ

### フェーズ1: Push & 動的フォールバック
- watch作成/更新/寿命30%前の再作成、重複排除、p95×3によるポーリング切替、一次メトリクス/アラート

### フェーズ2: 繰り返し/例外
- `singleEvents=true`展開、例外個別扱い、**過去4週/未来12週**の可変ウィンドウ

### フェーズ3: リンクUI & 双方向同期
- 「Googleとリンク」チェック（既定OFF）実装、GCard/TCard/Unlinkedごとの挙動、**自己更新スキップ**・**If-Match**・冪等キー

### フェーズ4: 再同期/手動リトライ & 取消/再リンク
- 「今すぐ同期」常設ボタン、保存直後のスナックバー、`status=cancelled`/削除のUnlinked化、再リンク候補UI

### フェーズ5: 観測性強化/SLO
- p95ダッシュ、DLQ/再試行可視化、運用Runbook

### フェーズ6: QA/仕上げ
- DST/複数TZ/大規模繰り返し/高負荷での回帰、文言/空状態/エラー状態の磨き込み

> 依存関係: 0 → 1 → 2 → 3 → 4 → 5 → 6

## 3. 受け入れ基準（抜粋）
- 双方向同期：Taesk編集→Google、Google編集→Taesk がp95≤60sで反映。
- 競合：If-Match不一致時に再取得→新しい側採用。自己更新は取り込みでスキップされる。
- 繰り返し/例外：例外編集/単発キャンセルが正しく展開・反映。
- 終日：GCardはDST/TZ跨ぎでもズレなし。  
- 取消/解除：Googleキャンセル/削除でUnlinked化し、再リンク可能。  
- 観測性：Push停止→動的ポーリング→復旧→停止がメトリクスに可視化。

## 4. 確認点（未決として残す）

### 4.1 Taeskカード（Unlinked/Linked後のローカル）の**終日表現**
- **案A（統一）**: GCardと同一実装（date + display_tz + start/end_utc冗長保持）  
  - メリット: 一貫性・DST耐性が高い / 実装の再利用が効く  
  - デメリット: 実装/保持コストやや増
- **案B（簡易）**: 00:00–24:00の時刻イベントとしてUTC換算のみ  
  - メリット: 単純・軽量  
  - デメリット: DST/TZ跨ぎで表示ズレの可能性
- **現状提案**: **案A に寄せる**（性能懸念等が出た場合にのみ案Bを検討）
>> GoogleCalendarと同じ仕様で
>> 「date + display_tz + start/end_utc」で合わせる方針自体はOK
>>（ただしdisplay_tz は「表示用」ではなく「解釈する基準TZ」という意味にしておくのがポイント）らしい
>> 終日をTGCardとした場合は、A/Bリストに入る動きでいきます。
>> GCardの終日は現在のヘッダー下にGoogleCalendarと同じように、帯状に表示を入れたい。
>> このデザインが壊れないように、このデザイン実装を最初にやってきちんと表示されるのを確認してからv3実装が安全かと思う。

## 付録: API/実装メモ
- 取得: `events.list`（`singleEvents=true`, `showDeleted=true`）, `syncToken`運用, `timeMin/timeMax`はウィンドウ連動
- Push: `channels.watch`/`channels.stop`、寿命30%前再作成、並走期間の冪等処理
- 競合: `If-Match`/`etag`で保護、**自己更新スキップ**を徹底
- レート: 429/5xxは指数バックオフ、最大待機15分
