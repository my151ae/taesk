## TL;DR（今回の主な決定）
- **Googleカレンダーカード**を新設。Google発イベントはまずこれとして**タイムライン**に表示。
- **終日（1日）タスク**は、Googleカレンダー同様に**ヘッダー直下の専用枠**に表示。
- **編集トリガ**：GoogleカレンダーカードをTaesk側で開いて編集した瞬間、**Taeskカード + Google接続カード**（＝双方向リンク済みの通常カード）へ昇格。
- **Googleイベント削除時**：カードは**Taesk上に残す**（**未接続カード**に遷移）。**期日/時間はクリアしない**。バッジで未接続を明示。
- **未紐付けイベント**の定義：上記の「紐付けされていない**Googleカレンダーカード**」。インボックス的なビューで扱う。
- **繰り返し**：まずは **B案（`singleEvents=true` 展開）**で実装。将来、親+例外モデルへ拡張可能性を残す。
- **新規/カレンダー移動など**：10-2のポリシーに準拠（まずGoogleカレンダーカードとして取り込み、以後の遷移は同じ）。
- **参加者/招待**：**方針A（読み取りのみ）**でv3は完結。編集/RSVPは以降のバージョンで検討。
- **通知遅延と冗長化**：**方針B（Push + 5〜10分フォールバックポーリング）**。通常はPush主体、異常時のみポーリング。
- **複数アカウント/カレンダー**：**方針B**。データモデルは複数前提、**UIは当面メインのみ**選択可。

## 0. 用語
- **Googleカレンダーカード（GCard）**：Googleで作成されたイベントから生成され、Taeskに表示される“読み取り主体”カード。未編集/未接続の状態。
- **Taeskカード（TCard）**：Taesk標準の編集可能カード。
- **Google接続カード（Linked TCard）**：TCardがGoogleイベントと双方向リンクされた状態。ETagなどの同期メタを保持。
- **未接続カード（Unlinked TCard）**：リンクが切れた（例：Googleイベント削除）後もTaesk上に残るカード。期日/時間は維持する。

状態遷移（概要）：
```
Googleイベント → [取込] → GCard
GCard → [Taeskで編集] → Linked TCard（TCardに昇格＋接続）
Linked TCard → [Google側削除] → Unlinked TCard（期日/時間維持＋未接続バッジ）
GCard/Unlinked TCard → [手動で既存TCardに紐付け] → Linked TCard
```

## 1. データモデル
### 1.1 共通フィールド
- `id`, `user_id`, `board_id`, `title`, `description`
- **日時**：`is_all_day`, `start_at_utc`, `end_at_utc`, `all_day_tz`（終日のズレ防止／表示用）
- メタ：`created_at`, `updated_at`, `deleted_at (nullable)`

### 1.2 Google連携メタ
- **イベント識別**：`google_event_id`, `ical_uid`
- **同期制御**：`google_etag`, `last_synced_at`, `sync_token`
- **リンク状態**：`link_state ∈ {gcard, linked, unlinked}`（= GCard / Linked TCard / Unlinked TCard）
- **監査**：`last_error_code`, `last_error_at`

### 1.3 Watchチャネル（別テーブル）
- `watch_channel_id`, `watch_resource_id`, `calendar_id`, `watch_expire_at`, `status`, `last_refresh_at`
- 再作成履歴・エラー履歴を保持

## 2. UI/UX
### 2.1 タイムライン表示
- **GCard**：Googleアイコン＋「未接続」チップ。クリックで詳細（読み取り）パネル。
- **終日**：**ヘッダー直下の専用行**に集約表示（ドラッグで日付移動／長押しで接続/紐付けアクション）。
- **Linked TCard**：通常カードと同様の見た目＋「Google接続」チップ。
- **Unlinked TCard**：通常カード＋「未接続」バッジ（復接続／削除ショートカットを提供）。

### 2.2 未紐付けビュー（インボックス）
- 対象：**GCard（未接続）**。
- 機能：検索、期間フィルタ、**近似マッチ候補（タイトル＋開始時刻）**提示 → 「新規TCard作成」/「既存TCardに接続」。
- 保持方針：無期限（上限件数超過時は古い順で通知＋アーカイブ、運用で調整可）。

----

## 3. 同期・フロー
### 3.1 取り込み
- `events.watch` でPush受信 → `events.list(syncToken)`で差分取得（`showDeleted=true`）。
- 初回/410/404時はフル再同期。ページング完了まで回収。

### 3.2 編集・競合
- Taesk→Google更新は **`If-Match`（ETag）**を必須にしてロストアップデート防止。
- 競合は **更新日時が新しい側**を採用（方針A）。失敗時は再読込→再試行。

### 3.3 削除・接続解除
- **Google側削除**：Linked TCard → **Unlinked TCard**（**期日/時間は維持**）。UIで「復接続」「完全削除」を提供。
- **Taesk側から接続解除**：Linked TCard → Unlinked TCard（Google側は変更しない）。

### 3.4 繰り返し（方針B）
- `singleEvents=true` で**インスタンス展開**。例外編集・単発キャンセルも反映。
- 負荷対策：期間/件数上限、早期終了（空差分時）、ページング監視。

### 3.5 カレンダー移動・新規（10-2準拠）
- 新規・別カレンダー移動イベントは**まずGCard**として取り込み。
- `ical_uid` と近接時間で既存Linked TCardへの**自動引継ぎ候補**を出すが、**最終確定は手動**。
- 不一致時はGCardとして残置（未紐付けビューでも操作可）。

### 3.6 通知遅延・冗長化（方針B）
- 通常は**Push主体**。**5〜10分間隔のフォールバックポーリング**は**異常時のみ有効化**。
- watch期限は `watch_expire_at` を監視し、残30%時に再作成。

----

## 4. 参加者/招待（方針A）
- v3は**表示のみ**（主催者、参加者、会議URL、出欠ステータス）。
- 参加者追加/RSVP編集/招待送信は対象外（将来拡張）。

----

## 5. セキュリティ・運用
- OAuth最小スコープ、refresh_tokenの安全保管。
- Webhook：`X-Goog-Channel-Token` 検証、冪等性キーで重複排除。
- レート制御：指数バックオフ＋ジッタ、429/5xxで再試行、DLQ運用。
- 監査ログ：誰が何を同期・解除したかの最小記録（PII最小化）。

----

## 6. 受け入れ基準（抜粋）
- 単発/終日イベントの作成・更新・削除が**双方向**で p95 ≤ 60秒（Push）。Push断時も**10分以内**に追随。
- Google削除→**Unlinked TCard**化し、**期日/時間は維持**。復接続/完全削除がUIから実行可能。
- 繰り返し（展開方式）で例外編集・単発キャンセルが反映される。
- 競合でロストアップデートが発生しない（If-Match）。

----

## 7. 実装タスク（Issue粒度）
1. **モデル**：`link_state`/Googleメタ追加、watchチャネルテーブル、`ical_uid`。
2. **取り込み**：watch + list(syncToken)、フル再同期、例外ハンドリング。
3. **UI**：タイムラインGCard/Linked/Unlinked 表示、**終日枠**、未紐付けビュー。
4. **編集昇格**：GCard→Linked TCard 変換処理、ETag付き更新。
5. **削除/解除**：Google削除→Unlinked TCard 遷移、復接続/完全削除操作。
6. **ポーリング**：異常時フォールバック、ヘルスチェック、watch再作成。
7. **観測性**：メトリクス/アラート、ダッシュ、再同期ボタン。
8. **ドキュメント**：ユーザーガイド、運用Runbook、SLO。
