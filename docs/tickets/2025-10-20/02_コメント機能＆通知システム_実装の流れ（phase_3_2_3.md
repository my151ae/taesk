## 2. アーキテクチャ概要
```
ユーザー操作（コメント投稿 / 返信 / @メンション）
   └─▶ API Routes（`/api/cards/...` / `/api/notifications/...`）で validate → persist
        ├─▶ Supabase DB: comments / comment_mentions / notifications
        ├─▶ Realtime: Comments / Notifications チャネル購読で UI 即時反映
        ├─▶ Sync Queue: オフライン時は既存キューに enqueue → 復帰後に API 実行
        └─▶ 通知生成（@mention, 期限, カード更新）
               ├─▶ アプリ内通知（bell）
               └─▶ Web Push（Service Worker経由）
```

### 2.1 通知チャネル
- **In-App**: ヘッダーのベル、未読数バッジ、通知ドロワー
- **Web Push**: Service Worker + Push API + Notifications API（VAPID/FCM いずれか）
- **Badging（任意）**: PWAアイコンに未読バッジ（対応環境で有効化）

### 2.2 iOS要件（重要）
- iOSでのWeb Pushは**ホーム画面に追加されたPWA**のみ対応
- **ユーザー操作**発火でのみ通知許可を要求（Install → 許可ボタン）

## 3. 仕様詳細

### 3.1 コメント機能
**機能**
- ルートコメント / 返信（`parent_id`）
- 編集・削除（権限: author or editor）
- メンション: `@` でボードメンバーをタイプアヘッド、本文保存時に抽出

**データモデル（提案）**
- `comments(id, card_id, board_id, author_id, parent_id, body, mentions uuid[], created_at, updated_at, deleted_at)`
- `comment_mentions(comment_id, mentioned_user_id)`（正規化: 通知生成/検索高速化。既存の `mentions` TEXT[] は API 互換のため継続）
- 既存 API（`/api/cards/[cardId]/comments` / `/api/comments/[commentId]`）は `mentions` 配列を返す前提なので、エンジン側で comment_mentions と配列を常に同期させる。

**AC（受け入れ基準）**
- [ ] 1秒以内に投稿が反映（楽観更新→確定）
- [ ] 返信が階層構造で表示/折り畳み可能
- [ ] メンションのハイライト/hoverでユーザーカード
- [ ] E2E: 新規/編集/削除/返信/メンションが通る

### 3.2 通知の自動生成
**イベント→通知ルール**
- コメント作成 → カード関係者（作成者/アサイニー/参加者）へ通知
- **@メンション** → 対象ユーザーへ必ず通知
- 期限リマインダー（将来） → 締切前N分/時間/日

**データモデル（提案）**
- `notifications(id, recipient_id, type, payload jsonb, read_at, created_at)`※`type` は `mention | assignee_changed | due_soon | comment_reply`
- `notification_preferences(profile_id, in_app_enabled, web_push_enabled, quiet_hours jsonb, updated_at)`
- 既存の `Notification` 型（`lib/supabase.ts`）と互換に保つ。未読判定は `read_at is null` を採用し、バッジ数は既存クエリでそのまま算出する。

**AC**
- [ ] コメント/メンションで未読通知が生成
- [ ] 既読化でバッジ減算、既読は復元されない
- [ ] データ整合性（重複通知を防止、冪等化）

### 3.3 Web Push
**クライアント**
- Service Worker: `sw.js`（`push`/`notificationclick`/`pushsubscriptionchange`）
- 購読: `registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })`
- 許可UX: 明示ボタン（Permission Promptは**ユーザー操作時のみ**）
- 購読情報保存: `push_subscriptions(user_id, endpoint, p256dh, auth, ua, installed_pwa)`

**サーバー**
- 送信: Edge Function（Deno） or API Route で VAPID署名 → Web Push送信
- 冪等: endpoint重複/410 Gone時のクリーンアップ
- レート制御: 1ユーザー/分あたり上限、バッチ配信/リトライ

**AC**
- [ ] Chrome/Edge/Firefox（デスクトップ）で受信
- [ ] Android Chromeで受信
- [ ] iOS 16.4+（PWA）で受信
- [ ] 許可/拒否の状態遷移テスト

### 3.4 Badging（任意）
- インストール済みPWAで `navigator.setAppBadge(count)` により未読数を表示
- 非対応環境では無害にフォールバック
