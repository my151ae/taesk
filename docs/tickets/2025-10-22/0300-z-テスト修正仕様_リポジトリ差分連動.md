# 0300 テスト修正仕様（リポジトリ差分連動）

**作成日**: 2025-10-22  
**対象ブランチ**: `main`（my151ae/taesk）  
**目的**: 最新の実装（リポジトリ）と E2E/統合テストの不整合を解消し、安定的にグリーン化する。

---

## 1. 現状整理（差分の事実）

- **アサイン機能の実装状態**
  - UI/型は **単一アサイニー**（`assignee_id: string | null`）運用。
  - 旧 `assigned_to` からの移行互換が残存（サーバ／E2E フォールバックあり）。
- **カードモーダルのナビゲーション**
  - `?card=<short_id>` の **クエリパラメータ方式**でモーダルを制御。
  - 旧 `/c/<short_id>` ページ遷移期待は廃止。
- **モーダルの挙動**
  - **Save 後もモーダルは閉じない**（手動で Escape などで閉じる）。
- **コメント機能**
  - `CardModal` に Comments パネルを **統合済み**（Zustand ストア + REST ルート）。

> 注: 上記はすべて現行リポジトリの実装に基づく。テスト側の前提（2 カラム化 / コメント統合は一致、一方、**マルチアサイニー（`assignee_ids: string[]`）は未実装**）。

---

## 2. 失敗テストと原因（テスト ⇄ 実装のズレ）

| テスト項目 | 期待（テスト側） | 実装（リポジトリ側） | 原因分類 |
|---|---|---|---|
| **メンバー選択（multi-assignee）** | `assignee_ids` に選択ユーザが保存される | 単一 `assignee_id` のみ | **仕様不一致**（機能未実装）|
| **Save 後にモーダルが閉じる想定** | Save クリックで閉じる | Save 後も開いたまま（Escape で閉じる） | **UI 挙動変更未反映** |
| **直接遷移でフルカードページ** | `/c/<id>` でページ表示 | `?card=<short_id>` でモーダル表示 | **ルーティング仕様変更未反映** |
| **URL 正規化（slug 不一致）** | 旧挙動前提の期待 | `?card` 準拠の正規化 | **ルーティング仕様変更未反映** |
| **コメント関連（phase3-comments）** | 旧 create フロー前提 | 「+ Add Card」→ 即時 `New Card` 作成 | **カード作成フロー変更未反映** |

---

## 3. 解決方針の選択肢

### A. いまは実装にテストを合わせる（推奨 / 所要が最短）
- **採用仕様**: 単一アサイニー（`assignee_id`）。
- **対応内容**:
  1) multi-assignee を仮で **テストから撤回**（配列前提の期待を `assignee_id` 前提に置換）。
  2) Save 後のアサーションは **Escape で閉じる**前提に修正。
  3) 直接遷移や URL 正規化は **`?card=<short_id>`** 前提に書き換え。
  4) コメント系は **新しいカード作成フロー**（"+ Add Card"→`New Card`）に追従。

### B. 機能をテストに合わせて拡張（中〜大工数）
- **採用仕様**: **マルチアサイニー**（`assignee_ids: string[]` + UI チップ）。
- **対応内容**（抜粋）:
  - DB スキーマ: `cards.assignee_ids uuid[]` 追加、`assignee_id` と二重運用または置換。
  - API: upsert／select の型・payload を `assignee_ids` 前提へ。
  - UI: CardModal の選択 UI をチェックボックス／チップ化、Save で配列を送出。
  - 移行: 旧 `assignee_id` → `assignee_ids[0]` のマイグレーション。
- **備考**: 0300 のスコープでは範囲外になりやすい。0310 以降に計画移行が妥当。

> 本仕様では **A 案（テストを実装に整合）** をデフォルトとして記述。

---

## 4. 具体的修正手順（A 案）

### 4.1 kanban.spec.ts（メンバー選択）
- **期待値の置換**: `assignee_ids` 配列 → **単一の `assignee_id`** 検証に変更。
- **UI 操作**: メンバーは `<select aria-label="Assignee">` で `selectOption(userId)`。
- **保存／閉じる**: `Save` → 1.5s 待機 → `Escape` → ダイアログ閉鎖を確認。

**サンプル（概念差分）**
```ts
// Before: expect assignee_ids to contain user
await expect.poll(fetchCard).toMatchObject({ assignee_ids: [TEST_USER_ID] });

// After: expect assignee_id equals user
await expect.poll(fetchCard).toMatchObject({ assignee_id: TEST_USER_ID });
```

### 4.2 kanban.spec.ts（URL 系）
- **直接遷移 / 状態保持**: 旧 `/c/<id>` ではなく、`?card=<short_id>` を **URL 期待**に変更。
- **正規化**: slug 不一致時も **クエリパラメータ方式**での正規化をアサート。

**サンプル**
```ts
await expect.poll(() => page.url()).toContain(`card=${shortId}`);
```

### 4.3 phase3-comments.spec.ts（カード作成フロー）
- **ヘルパー**: `createTestCard` は **タイトル入力をやめ**, `"+ Add Card" → "New Card" 自動作成**に準拠。
- **選択**: `page.getByText("New Card").last().click()` でターゲットカードを特定。
- **Comments UI**: モーダル内タブではなく、**右カラムの Comments** を前提に探索。

### 4.4 テスト安定化（共通）
- **Save 後の待機**: `waitForTimeout(1500)` を標準化（DB ラウンドトリップ + UI 反映待ち）。
- **非同期ポーリング**: 重要フィールドは `expect.poll(fetcher)` で DB 値確定を待つ。
- **ワーカー数**: 並行実行競合がある場合は一時的に `--workers=1`。

## 5. 参照コード影響（確認観点）

- **CardModal**
  - `assignee_id` の state／props 流れ（`onSave(id, ..., assigneeId, assigneeTouched, ...)`）。
  - メンバー検索は `profiles`（＝ボードメンバー）前提。
- **KanbanBoardClient**
  - `onSave` ハンドラで `assignee_id` を upsert するロジック。
  - モーダル開閉・URL 連動は `?card=<short_id>` を採用。

> 試験観点: Save ボタン押下で `cards.assignee_id` が **NULL→ユーザーID** に変化し、再オープン時に `<select>` の `value` と一致すること。

## 8. 追補：将来のマルチアサイニー（B 案ラフ仕様）

- **DB**: `assignee_ids uuid[]` 追加、読み書きは `assignee_ids` を正とする。

- **テスト**: E2E を `assignee_ids` 検証に再置換、単一→複数の両ケースを追加。
