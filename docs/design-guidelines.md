# Design & Implementation Guidelines

このドキュメントでは、Taesk プロジェクトにおけるデザイン実装、特にレスポンシブ対応と Next.js (App Router) におけるハイドレーションエラー回避のための方針を定義します。

## 📱 レスポンシブ実装の基本方針

Next.js での SSR 時のハイドレーションエラーを避けるため、**JS の画面幅判定（`window.innerWidth` 等）ではなく、Tailwind CSS のユーティリティクラスで表示/非表示を切り替える方針**を基本とします。

### 1. 基本パターン（最優先）

ロジックやデータ取得は共通のまま、Tailwind CSS のユーティリティクラス（`hidden`, `block`, `md:block`, `md:hidden` など）を使って、表示するコンポーネントを出し分けます。

**AI への指示プロンプト例:**
> 「このプロジェクトで PC とスマホで UI を分けたいです。
> ロジックやデータ取得は共通のままにして、
> Tailwind CSS のユーティリティクラス（hidden, block, md:block, md:hidden など）を使って、表示するコンポーネントを出し分けてください。
>
> Next.js（App Router）で SSR 時のハイドレーションエラーを避けたいので、
> window.innerWidth などの JS による画面幅判定ではなく、CSS のレスポンシブ制御で実装してください。」

### 2. コンポーネント単位での切り替え（テーブル vs カード）

一覧画面などで、PC ではテーブル、スマホではカード形式といったように、コンポーネント単位で UI を切り替えたい場合のパターンです。

**AI への指示プロンプト例:**
> 「一覧画面の実装についての依頼です。
>
> **PC 画面（md 以上）**では TableComponent を使って、詳細な情報をテーブル形式で表示してください。
>
> **スマホ画面（md 未満）**では CardComponent を使って、情報を簡略化したカードを縦に並べて表示してください。
>
> 両方のコンポーネントには、同じ props（同じデータ構造）を渡すようにしてください。
>
> 画面幅による出し分けは、Next.js の SSR でハイドレーションエラーを避けるため、
> Tailwind CSS のクラスで表示/非表示を切り替える実装にしてください（hidden / md:block など）。」

### 3. レイアウト全体の切り替え（ナビゲーション等）

サイドバーやボトムナビゲーションなど、レイアウトレベルでデバイスごとに切り替えたい場合のパターンです。

**AI への指示プロンプト例:**
> 「レイアウトファイル（Layout.tsx）の実装についてです。
>
> **PC 表示時（md 以上）**は左側に Sidebar コンポーネントを常時表示してください。
>
> **スマホ表示時（md 未満）**は画面下部に BottomNavigation を表示するように切り替えてください。
>
> メインコンテンツ（children）は PC / スマホ共通で表示したいです。
>
> 表示切り替えは、Next.js の SSR との相性を考えて、
> JS の画面幅判定ではなく Tailwind CSS のクラスで制御してください。」

## 🚫 禁止事項と対策

### `window.innerWidth` の使用禁止

AI が以下のようなコードを提案してきた場合は、ハイドレーションエラーのリスクが高いため却下してください。

```tsx
// ⚠️ Next.js では望ましくない例
if (window.innerWidth < 768) {
  return <MobileView />
}
```

**修正依頼のプロンプト例:**
> 「このプロジェクトは Next.js（App Router）なので、
> サーバーサイドレンダリングとの兼ね合いでハイドレーションエラーが心配です。
> window.innerWidth などの JS ではなく、CSS（display: none / block や Tailwind の hidden / md:block など）での切り替えに書き直してもらえますか？」

## 🔑 有用なキーワード

AI に指示を出す際、以下のキーワードを含めると意図が伝わりやすくなります。

- **「条件付きレンダリング (Conditional Rendering)」**: JS で中身を切り替えるときに使う用語（SSR に注意）。
- **「ビューの切り替え」**: ロジックではなく「見た目だけ」変えたい意図を伝える。
- **「レスポンシブなコンポーネント置換」**: CSS で幅を変えるだけでなく、コンポーネントごと差し替えたい場合。
